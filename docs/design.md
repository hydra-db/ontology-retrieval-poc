# Decision and research notes

This POC combines a deterministic ontology with linked chunk vectors. Asynchronously learned user snippets compose bounded retrieval strategies, and a cross-encoder is optional. It deliberately excludes arbitrary query generation, proposals, digests and source-system write-back. All example records, people and publication summaries are synthetic; source-provider API endpoints and public research references are the only live links.

## Minimal stack and store boundaries

Python 3.12 + SQLite keeps this one repo runnable with no credentials or services. Nodes/edges form the typed ontology, chunks hold source offsets and persisted embeddings, and preferences have a separate logical schema in the same transactional database. This is a local behavioral reference, **not a HydraDB backend integration or HydraDB benchmark**. Replacing Store with HydraDB graph/vector calls is a future integration boundary; no hosted database was touched.

The zero-dependency default is explicitly **lexical cosine over token counts**, not dense vectors or semantic understanding. The neural option uses pinned all-MiniLM-L6-v2 (384 dimensions, CPU) and optional pinned MS MARCO MiniLM-L6 cross-encoder, both loaded exclusively from local directories. Setup downloads are explicit; queries never download. Chunks retain the exact full body without truncation at 600-character boundaries. Encoder input includes the title plus body chunk. The model may truncate tokenization on unusually token-dense text; production chunking should use tokenizer bounds. The complete body remains persisted regardless. Abstracts are the complete arXiv feed text; PDFs are not fetched or represented as full-paper text.

Node IDs are `source:type:escaped-provider-id`; chunks hash node ID, body offset and exact text; tenant participates in every primary/foreign key. Comments and replies are distinct types. People merge only on source account IDs. Fireflies speakers remain meeting-local; authors lacking an explicit ID remain publication-local. Display-name equality never merges people, and cross-provider identity isn't guessed. Raw source metadata, body, URL, author edges and chunk offsets retain provenance. Reingestion upserts records and replaces their outgoing edges/chunks. Omitted records aren't interpreted as deletions; deletion must be explicit.

## Non-generative retrieval

1. A closed grammar resolves supported intent, explicit issue ID and type. Unsupported/ambiguous requests abstain without store reads. Only predefined SQL strings with bound values exist; no generated SQL/Cypher or plans.
2. Exact issue authorship uses the ontology only. It never reads preferences, chunks or an encoder. Unknown/duplicate identifiers abstain instead of broadening the search.
3. Explicit issue content search traverses a fixed three-level comment/reply scope (maximum 1,000 nodes), then ranks its chunks. In neural mode this uses 0.75 dense cosine + 0.25 lexical cosine, a transparent uncalibrated experimental weighting. Default lexical mode does not claim hybrid dense retrieval.
4. Content-only retrieval can skip personalization. Otherwise relevant per-user aliases are selected by exact token match and confidence >=0.9, at most five. They only replace query tokens; they cannot change permissions, ontology IDs or templates. No match/low confidence falls back to the unpersonalized query. A local cross-encoder optionally reranks at most twenty chunks. Results are quoted source candidates, **not generated answers or confirmed research recommendations**.

Router confidence fields are rule certainty labels, not calibrated probabilities. The corpus measures the base route before alias application; separate tests prove the personalized path. A small fixed grammar intentionally sacrifices paraphrase coverage, which is disclosed rather than hidden by tuning against the holdout.

## Background learning and safety

`learn` is a separate, repeatable job over immutable transcript turns. It processes at most 1,000 unseen events each invocation, keeps an extractor-version checkpoint per event, validates exact evidence and timestamps, and supersedes aliases by said-at time (UTC), then event ID. Late older evidence never replaces newer evidence. Original superseded rows remain until deletion. Rerunning with a new extractor version is possible; the evidence validator still controls admissible writes.

An alias evidence watermark includes explicit turns even when the extractor abstains. A newer explicit contradiction disables the stale alias rather than silently continuing to personalize with it; unaccepted new evidence falls back to unpersonalized retrieval. Older events cannot resurrect an alias past that watermark.

The offline mode only recognizes a complete first-person sentence such as `I use turbolay to mean hydradb.` It is labeled deterministic, not LLM extraction. A pluggable background command can invoke an LLM and return structured JSON, but its output is accepted only when the entire user turn supports that explicit alias and exact quote. Assistant/tool messages, concatenated instructions, unsupported schema, invented evidence and confidence below 0.9 are rejected. This is deliberately narrow: implicit preferences and general transcript reasoning need a separately evaluated schema, stronger review, and extraction precision/recall data. The POC does not claim that prompting alone solves injection.

Deletion removes the user's preference and source-turn evidence and leaves a content-free key tombstone to stop replay resurrection. `forget --key` permanently disables relearning that alias until an operator removes the tombstone; no restore API is provided. Deletion isn't a source-system delete. SQLite files, backups, swap and filesystem recovery are outside the POC's privacy guarantees; secure erasure/encryption and retention are deployment work.

Deletion normalizes key casing, covers pending explicit-alias evidence, and retains content-free source-event tombstones. Exact supported alias records with a forgotten key are rejected even if replayed under a new event ID. Deleting one alias doesn't delete another alias's evidence merely because it mentions that word as a value. These are scoped record-deletion guarantees, not a global ban on the same word appearing in future arbitrary transcript text.

Tenant and user are trusted local CLI parameters, not authentication. Source visibility is tenant-wide; per-document ACLs and authenticated principal mapping are not implemented. Don't expose this CLI as a multi-user service. Raw transcript/customer sources must be consented and access-controlled before any live ingestion. No secrets belong in fixtures or database exports; live credentials are environment variables and never persisted by the fetchers.

## Polling and evaluation boundaries

The read-only arXiv job accepts explicit topics, polls at most twenty records per topic, deduplicates provider IDs, overlaps checkpoints by one day, and atomically saves a durable inbox/checkpoint before ontology ingestion. Every run replays the inbox, so an ingestion failure is recoverable. Cold start selects only newest papers; incremental overflow fails rather than silently skipping records. Topics are exact checkpoint namespaces; revised papers with changed arXiv version IDs are separate records. No production scheduler or write-back exists. A one-day overlap cannot guarantee discovery of arbitrarily late-indexed papers; a future reconciliation backfill is required for completeness.

Tests block sockets during fixture queries and neural model loads/queries, and block subprocess LLM invocation on the normal query path. `network_calls`/`generative_calls` fields describe the designed path, not an OS-level telemetry counter. Measured latencies distinguish initialization, first request and warm median/p95. A subprocess benchmark additionally captures interpreter/model-load time with filesystem caches uncontrolled. Synthetic holdout accuracy, route misses, local model configuration, data size and raw outputs are committed. No customer relevance labels, production load, extraction-LLM cost or benchmark-scale search claims are made.
